# AWL（分析ワークアウトログ）

iPhone Safari向けのトレーニング記録アプリです。手入力・標準キーボードの音声入力・履歴編集・JSONバックアップに対応します。

## データは3階層で管理します

1. セッション：1回のトレーニング。日付・場所・運動時間・体調を1回だけ保存します。同じ日の昼と夜は別セッションにしてください。
2. 種目：種目名・対象部位・共通メモ。同じセッションの同じ種目は1枚のカードです。痛み・違和感・フォーム・疲労感はメモに書きます。
3. セット行：重量・回数・セット数。例「80kg × 10回 × 1セット」「75kg × 8回 × 2セット」を別の行として登録します。

体調は従来の1〜5（悪い〜良い）を維持します。メモと体調をセットごとに繰り返し入力する必要はありません。同じ種目への追加では既存メモを残して新しいメモを追記し、同じ文章は重複させません。部位が食い違う場合は自動採用せず、入力の修正を案内します。

## 最初に旧記録のバックアップと移行を確認してください

履歴の「データ保護・移行確認」で、まず「移行前の元データをJSON保存」を押し、ファイルを保管してください。

- 旧保存領域 `shiba-train-log-v1` は上書き・削除しません。新しい記録は別の `shiba-train-log-v2` に保存します。
- 読み込みだけでは新保存領域に書き込みません。「確認済みの構造を保存」、旧記録の確認後の移行、新規記録の保存など、保存操作をした時に書き込みます。
- 同じ日付という理由だけでは統合しません。以前の自動統合で作成された可能性のあるセッションIDも、区別を保証できないものは「要確認」にします。
- 新しい形式のセッション情報、または明示的な音声一括入力の情報があり、場所・体調・時間などが一致する記録だけ、対応するセッションへ安全に変換します。それ以外は元の値のまま「要確認」に残します。
- 要確認の記録は履歴に表示し、重量などの集計には含めます。確認済みセッションの運動時間・平均体調には含めず、元の時間や体調を別表示します。
- 同じトレーニングに属すると確認できた旧記録だけをチェックし、日付・場所・全体の時間・体調を指定して「1セッションへ移行」を押します。朝・夜や会社・自宅を混ぜて選択しないでください。
- 同じ種目で元の部位が異なる場合は、その種目の共通部位を選び直せます。未選択のまま勝手に統合しません。
- 元のID・体調・メモ・痛み・炎症・その他の項目は、新JSONの `legacyArchive` にそのまま保管します。異なるメモは共通メモに併記し、旧痛み・炎症もメモへ移します。
- 要確認の記録は、整理が済むまで直接編集・削除・並べ替えを止めています。保存失敗時は元の記録と移行画面の入力を保持します。

過去の90分などが正しいかは、記録だけでは判断できない場合があります。時間を自動で合算・平均化・補正せず、移行確認で正しいセッションと時間を指定してください。

## 手入力の使い方

1. 「記録する」の手入力フォームで日付を選びます。
2. 新しいトレーニングでは「新しいセッションを追加」を選び、場所・全体の運動時間・体調を入力します。
3. 種目名・部位を選び、重量・回数・セット数を行ごとに入力します。必要なら「セットを1行追加」を押します。
4. 種目のメモを1回入力し、「記録を保存」を押します。
5. 同じトレーニングの次の種目では、保存済みセッションが選択されたまま追加します。場所・時間・体調は入力済みになります。別のトレーニングなら「新しいセッション」を選び直します。

同じ種目を追加保存しても、同じセッション内では1枚のカードにまとまります。別セッションの同名種目は別カードです。既存の「その他」の場所も互換性のため残しています。

## 音声・文章入力の使い方

追加の月額費用や有料音声認識・AI APIは使いません。iPhone標準キーボードのマイクで文字を入力し、文章解析はブラウザ内で行います。

1. 「音声・文章からまとめて入力」で、日付・場所・セッション・時間・体調を設定します。下の手入力フォームとは別の未保存一覧です。
2. 文章欄をタップし、キーボードのマイクで1種目ずつ話します。
3. 例：「ベンチプレス80キロ10回1セット、75キロ8回2セット、右肩に違和感あり」。重量設定を2行に分け、違和感の文章を種目メモに振り分けます。
4. 「解析して追加」で未保存一覧へ入れ、種目・部位・セット行・共通メモを文字で修正します。「次の種目を追加」で続けます。
5. 「全種目を確認」→「確認して一括保存」で全種目をまとめて保存します。体調・時間はセッション全体に1回だけ保存します。

マイクが出ない場合はiPhoneの「設定 → 一般 → キーボード → 音声入力を有効にする」を確認してください。種目の部位は辞書の候補です。認識できない情報は推定せず、原文と未解析部分を残します。原文を書き換えた場合は「この文章で再解析」を押してください。

途中入力は `shiba-train-log-voice-draft-v1` に一時保存し、同じSafari・同じURLで再読み込みすると復元します。以前の種目別体調を含む下書きも、元の下書きを保管して共通の体調を選び直せます。旧体調・原文も保持します。一時データは通常のJSONバックアップとは別です。

保存失敗時は一覧と入力を残します。確定保存後に一時データの削除だけが失敗しても、`voiceBatchId` により再試行時の二重登録を防ぎます。

## 履歴・編集・並べ替え

- 日付は新しい順です。日別・週別表示と場所フィルターを使えます。
- 各日付の中にセッションを分けて表示し、場所・時間・体調はセッション共通で表示します。日別の時間合計は全場所の確認済みセッションを1回ずつ加算します。
- カード内はセット行と、カード下部の共通メモです。痛み専用の入力欄はありません。
- カード本体を約0.5秒長押し、または「編集」で、同じカード内の種目・部位・セット行・共通メモを編集できます。保存失敗時は入力を残し、キャンセルで元に戻ります。
- 時間表示の長押し、または「場所・時間・体調を編集」でセッション共通情報を変更できます。
- 「≡」の長押しで並べ替えます。同じセッション内のカードだけ移動できます。別セッションへ移動して所属を書き換える操作は行いません。上下ボタンも使えます。
- ドラッグ中はカードが浮き、移動先の中央を基準に前後を判定します。画面端ではゆっくり自動スクロールし、長いカードは移動中だけコンパクトになります。指を離す・中断する・Escapeを押すと自動スクロールを停止します。
- 通常のスクロールと編集の長押しは区別し、編集中は並べ替えを止めます。並び順と編集内容は再読み込み後も保持します。

## JSON・CSV・データ保護

- 「JSON書き出し（全情報）」：新しい3階層、移行待ち、元データの保管情報をすべて含みます。通常のバックアップにはこちらを使ってください。
- 「旧形式JSON書き出し」：従来の記録一覧として出力します。元データの保管情報など一部の新情報を表現できないため、全情報JSONの代わりにはなりません。
- 「JSON読み込み」：古い配列形式と新しい3階層形式の両方に対応します。従来どおり全件置き換えです。事前に現在のJSONを書き出してください。確認のキャンセルでは変更しません。
- 空・重複など不正な既存IDを自動で変更せず、読み込みを止めて元データを保護します。文字列の独自ID（`demo-1`など）はそのまま使えます。
- CSVは既存列を維持し、`sessionId`・`exerciseId` を追加しています。CSVや旧形式JSONは一覧のため、場所や体調などを各行へ展開します。実際の保存データはセッションに1回だけです。
- 集計は既存記録IDのセット行をもとに計算します。ChatGPT向け要約ではセッション情報と種目メモを重複させず、移行待ちは別に明示します。
- 保存は1回の書き込みで行い、成功してから画面・メモリを更新します。破損した新保存領域を検出した場合は保存を停止し、元データを保持します。
- 端末間の自動同期はありません。プライベートブラウズやSafariデータの削除では保持されない場合があるため、JSONを別の場所にも保管してください。

## Windowsで全自動テストを実行する

1. このREADMEのあるフォルダをエクスプローラーで開きます。
2. `run-tests.cmd` をダブルクリックします。
3. 日本語の「成功：○件 ／ 失敗：○件」を確認し、キーを押して閉じます。

通常の `node` コマンドが使えなくても、このPCのCodex同梱Node.jsを自動使用します。なければ通常のNode.jsを探します。追加ライブラリは不要です。`tests` 内のすべての `*.test.cjs` を実行し、詳細を `test-results.log` に残します（実行ごとに上書き）。失敗時は `not ok` の下の原因・ファイル名・行番号を確認してください。

自動テストでは仮の保存領域を使い、実際のSafariの記録を変更しません。古い形式の互換処理と、新しいモデルを使う起動・手入力・音声入力・移行・編集・JSON・CSV・要約を確認します。

## iPhone Safariで確認すること

1. 最初に全情報JSONと、移行前の元データをバックアップします。
2. 同じ日の会社40分・体調4、自宅20分・体調2を別セッションとして作り、合計60分になることを確認します。
3. 同じセッションにベンチプレスの異なる重量を追加し、1カード・複数行・メモ1回になることを確認します。
4. カード編集で重量とメモを変更し、保存・キャンセル・再読み込み後の保持を確認します。共通の体調・時間も変更してみます。
5. 音声入力で2種目を一時追加し、再読み込みで復元してから一括保存します。セッション時間や体調が種目数で増えないことを確認します。
6. 要確認の元の値を比較し、同じトレーニングの記録だけを選んで移行します。違う場所や体調を勝手に採用していないことを確認します。
7. 長押し編集と通常スクロールの区別、「≡」のドラッグ、縦長カードの自動スクロール、セッションをまたぐ移動禁止、再読み込み後の順番を確認します。
8. 日別・週別・場所フィルター、JSONの書き出しと読み戻し、CSVと要約も確認します。復元テストのための全件削除は不要です。

## 公開ファイルと残る制約

公開時は `index.html`、`training-data.js`、`session-app.js`、`voice-input.js`、`voice-ui.js` を同じフォルダに配置してください。新しい保存用ファイルを読み込めない場合は、旧保存領域への書き込みを止めます。

旧記録から元のセッションを確実に復元できない場合は、ユーザーの確認が必要です。複数の体調や部位の不一致を自動で平均化・上書きしません。元データを複製して保護する分、保存容量を多く使います。容量不足時は元データを消さずにエラーを表示します。

iPhone Safari実機のタッチ操作・音声認識・キーボード表示は自動テストだけでは確認できません。これらは実機確認が必要です。HealthKitの自動取得や新しい有料AI機能は追加していません。
